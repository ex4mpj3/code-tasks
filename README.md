# Задание №6. Вариант 8. Все распределения инвестиций

## Задание

Это задание повышенной сложности: за его выполнение можно получить дополнительные баллы.

В файле `main.py` реализовать функцию:

- `get_invest_distributions` — найти **все** распределения всех лотов по проектам с максимальной суммарной прибылью и вернуть именованный кортеж `Result` с полями `profit` и `distributions` (список планов).

Строки таблицы — уровни вложения (число лотов $k$), столбцы — проекты. Клетка $a_{s j}$ — прибыль, если проект $j$ получил $s+1$ лотов. Проекту можно дать ноль лотов: тогда его прибыль $0$. Вся сумма распределяется: сумма компонент каждого плана равна $k$, `distribution[j]` — сколько лотов ушло в проект $j$.

Пока заполняется таблица максимальной прибыли $F(i,j)$, **нужно сразу запоминать все выбранные распределения** на этом шаге (сколько лотов ушло в очередной проект, все аргументы максимума). Все планы собирают из этих сохранённых выборов. **Нельзя** восстанавливать планы отдельным перебором по уже посчитанной таблице $F$. Порядок планов в `distributions` не фиксируется. Повторы одного и того же плана недопустимы.

В `main.py` уже объявлены `ErrorMessages` (`StrEnum` со стандартной библиотеки) и `ProfitValueError`. Тексты ошибок брать из перечисления, не копировать строками. `ProfitValueError` принимает сообщение, `project_idx` (столбец) и `row_idx` (строка), индексация с нуля. Его нужно выбрасывать при отрицательной или убывающей по столбцу прибыли.

**В этом задании** таблица — список списков. Клетка — `int` или `float`; `bool` числом не считается. Иначе `TypeError` с `ErrorMessages.TABLE_NOT_NUMBERS`. Пустая или непрямоугольная таблица — `ValueError` с `ErrorMessages.TABLE_NOT_RECT`. Отрицательная прибыль — `ProfitValueError` с `ErrorMessages.NEG_PROFIT`. Если в столбце прибыль падает при росте вложения — `ProfitValueError` с `ErrorMessages.DECR_PROFIT`.

Пример использования — в `main.py`.

В файле `test.py` приведены примеры. Команда расширяет набор тестов, чтобы убедиться в корректности своего решения. При проверке учитываются и тесты команды, и дополнительные проверки преподавателя, которые в репозиторий не публикуются.

## По теме

**Динамическое программирование** опирается на принцип оптимальности Беллмана: оптимальное решение строится из оптимальных решений подзадач.

Есть $n$ проектов и $k$ неделимых лотов. $P_i(x)$ — прибыль от $x$ лотов в проект $i$, $P_i(0)=0$, а при $x\ge 1$ это клетка $a_{x-1,\,i-1}$. $F(i,j)$ — максимальная прибыль при первых $i$ проектах и $j$ лотах:

$$
F(0,0)=0,\qquad
F(i,j)=\max_{0\le x\le j}\bigl(F(i-1, j-x)+P_i(x)\bigr).
$$

Ответ — $F(n,k)$ и **все** наборы $(x_1,\ldots,x_n)$ с суммой $k$, на которых эта прибыль достигается. В этом задании все выбранные $x$ запоминают в тот же момент, когда считают $F(i,j)$. Планы собирают из сохранённых выборов, без повторного поиска по таблице $F$. Порядок наборов не фиксируется.
